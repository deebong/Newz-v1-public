Take this file anywhere


This page is 100 percent static. There is no server, no database, no account, and no build step. The file you are looking at is the whole tool: HTML for structure, CSS for styling, and JavaScript for everything interactive. Keep a copy anywhere — your desktop, a USB stick, Dropbox, or GitHub Pages. You need an internet connection only to fetch live headlines.


Open it on your own PC


    

  1. Save this file (in your browser: File > Save page as, or press Ctrl+S / Cmd+S).
    2. 

  2. Double-click the saved file — it opens in any modern browser (Chrome, Edge, Firefox, Safari).
    3. 

  3. Tip: if your browser restricts anything from a local file, serve the folder instead: open a terminal in the folder and run python -m http.server 8000 (or npx serve), then visit http://localhost:8000.
    4. 



Host this tool on GitHub Pages (free, no terminal needed)


    

  1. Create a free account at github.com and click New repository. Name it e.g. newz-tool, make it Public, and create it.
    2. 

  2. Click Add file > Upload files, add this file renamed to index.html, and commit.
    3. 

  3. Go to Settings > Pages. Under “Build and deployment”, set Source to Deploy from a branch, branch main, folder / (root). Save.
    4. 

  4. Wait about a minute, refresh the Pages screen, and open your link: https://YOUR-USER.github.io/newz-tool/.
    5. 

  5. To update later, upload a newer copy of the file — no rebuild ever required.
    6.

Which proxy should I use?


    

  • Default public proxy (pre-filled): zero setup, no signup. A third party relays feed requests, so it can be slower, rate-limited, or log traffic. Fine for personal use and testing.
    • 

  • Your own Cloudflare Worker (free tier): copy worker.js from step 4 into a new Worker, deploy, and paste its URL into Design > Advanced. Reliable and private — recommended if you publish your page.
    • 



Set up your own proxy with Cloudflare (5 minutes, free)


Your own proxy means your news page never depends on a public relay. Everything runs on Cloudflare's free plan and is protected against abuse.


    

  1. Sign in at dash.cloudflare.com (free account).
    2. 

  2. Left menu → Workers & Pages → Create → Create Worker → name it e.g. newz-feed → Deploy.
    3. 

  3. Click Edit code → select all → paste the whole worker.js file (from step 4) → Deploy.
    4. 

  4. Copy your worker address, e.g. https://newz-feed.yourname.workers.dev.
    5. 

  5. Here in the tool: Design → Advanced → Proxy URL = https://newz-feed.yourname.workers.dev/?url=. Optionally append &batch=1 so many feeds load in ONE request.
    6. 

  6. Press Test this proxy — it tells you immediately whether it works.
    7. 



Keeping it safe on the free plan: the worker only allows the curated feed domains, caps requests per IP, and caches each feed for 10 minutes — so repeat visitors cost almost nothing. Turn on Cloudflare's Settings → Security → Settings → Browser Integrity Check only if you see abuse; the allow-list already blocks it.




Free-plan safety (so you never get flagged)


    

  • Allow-list on: the worker only fetches the feed domains in the bundled list. Unknown URLs are rejected — this stops your worker being used as an open proxy.
    • 

  • Cached: each feed is cached for 10 minutes, so 100 visitors cost about 1 fetch, not 100.
    • 

  • Rate-limited: each IP is capped at 60 requests/minute.
    • 

  • Batch mode: add &batch=1 to fetch 20 feeds per request instead of 20 requests.
    • 

  • Nothing personal is stored: the worker keeps no visitor data and no accounts. Only feed XML is cached, briefly.
    • 

  • Attribution: keep the publisher credit on your page — that is the polite (and often required) way to use their feeds.
    • 



Please respect publishers


Headlines, summaries, and articles belong to the respective publishers. This tool shows them with attribution and links back to the original articles, for personal, non-commercial reading. It does not claim any feed may be reused: check each source's terms before redistributing, and always keep the attribution and source links intact.


Feeds can move, rate-limit, or disappear without notice. If a section shows an error, that source is temporarily unavailable — the rest of your page keeps working.
